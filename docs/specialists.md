# Specialist models

Specialist weapons use native WDS `ModifyItemOnSingle` options (`Type: 4`), the same existing-soldier mechanism used for T9A command models. They do not create extra units, reserve models, or additional soldiers. Ordinary Goliath and Immortal weapon upgrades remain unit-wide options.

Each selected specialist carries the existing `rule_keyword_specialist` rule as a direct model child. `icons.json` matches that exact rule ID to the custom transparent rank badge generated by `src/warhall/specialist-icon.mjs`. The client controls visibility through its normal soldier-icon preference and account feature availability; WDS does not force those preferences on.

The whole-unit profile omits specialist weapon tables. Each specialist's own model profile shows its actual weapon table and keywords, as well as its blue description link. Explicit FOR replacement notes remove that soldier's original weapon groups; the Rocket Launcher is a SIDEARM and retains the rifle. Unit-wide GetNewDefault excludes Type-4 modifiers, so ordinary unit tables are unaffected. Profiles with no positive base Shd characteristic omit that column; shielded profiles retain it.

The native Unit options labels are blue, underlined popup links. Their WDS IDs remain plain and stable for list imports and visual modifiers; the displayed Name contains the rich text. Popup IDs are short to stay within TMP link-tag limits.

## Native UI limits

Desired order is ordinary selected upgrades, specialist links, then Assault Phase, with no Unit options heading. The current WDSDisplayable hardcodes Type-4 names at the profile bottom under that heading; no supported WDS field changes this. In Leading Model movement, InputManager.DoubleClick also returns early through UseIndividualModelInput, disabling the T9A single-model-selection gesture. WDSPanel otherwise supports showing a selected Soldier's own logic. These two interaction/layout changes require native client work; this repository does not modify or patch it. The correct model-specific weapon data is maintained independently.

Size calibration uses the reviewed ordinary unit catalogue as reference. Uniformly scale the assembled specialist so its body mesh height matches the standard figure; exclude the added weapon from this comparison. The normal units are not changed. `specialist-model-report.json` records original and corrected heights and each adjustment. Both Marine specialists match the 32.9346-mm reference; both Infested Marine specialists match the 51.2275-mm reference. Final visual comparison in the client is still required.

`specialist-models.json` contains separate publication checkpoint keys, the real `assignmentProfileId`, and the exact native option IDs in `selectedOptions`. These option-specific skins must not replace the ordinary unit default. Publish with `npm run models:publish -- --kind specialist --server test --apply --login --accept-publication-terms` after pushing assets.
