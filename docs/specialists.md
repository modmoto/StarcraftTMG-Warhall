# Specialist models

Specialist weapons use native WDS `ModifyItemOnSingle` options (`Type: 4`), the same existing-soldier mechanism used for T9A command models. They do not create extra units, reserve models, or additional soldiers. Ordinary Goliath and Immortal weapon upgrades remain unit-wide options.

Each selected specialist carries the existing `rule_keyword_specialist` rule as a direct model child. `icons.json` matches that exact rule ID to the custom transparent rank badge generated by `src/warhall/specialist-icon.mjs`. The client controls visibility through its normal soldier-icon preference and account feature availability; WDS does not force those preferences on.

Specialist weapon profiles remain available through the selected upgrade description links. Their duplicate inline/collapsible weapon tables are omitted. Profiles with no positive base Shd characteristic omit that column; shielded profiles retain it.

Run `node scripts/models/prepare-specialist-models.mjs`, then rebuild the model catalogue. The preparation downloads actual meshes, textures and bundles, discards the library's decorative base, bakes attachment transforms and grounds the result. Bundle-authored root scale and reviewed launcher offsets are explicit source metadata. Do not restore the initial floating launcher placement.

`specialist-models.json` contains separate publication checkpoint keys, the real `assignmentProfileId`, and the exact native option IDs in `selectedOptions`. These option-specific skins must not replace the ordinary unit default. Publish with `npm run models:publish -- --kind specialist --server test --apply --login --accept-publication-terms` after pushing assets.

## Validation boundary

Local validation covers WDS references, option scope, retained weapon links, shield columns, skin binding payloads and rendered geometry. In Warhall Test, import each specialist alone and both specialists together, confirm unchanged model count, shared movement, the chosen model skins and the badge above specialist soldiers only. Also check other unit upgrades alongside specialist selection. Rendered previews and API readback are not substitutes for this client test.
