# Tokens and templates

The active WDS menu has 23 records, generated by src/tokens/package.mjs and ordered by token-menu-order.json:

1. Blast Template.
2. Blue and red activation markers.
3. Terran, Protoss and Zerg faction pairs.
4. Buff and Debuff.
5. Other effects alphabetically, with Corrosive Bile immediately after Bile Bomb.

Shield, separate Assault records, native Warhall colour tokens and the old 3-inch template are removed. Native unit shield statistics/HUD values remain intact.

## Map stacks

Every map contains two activation stacks per player side: 15 blue and 15 red markers, 60 markers total, outside the standard board edge. src/tokens/tray.mjs owns their positions and counts. Other available tokens are placed manually or supplied by the existing native ExtraItems definitions; do not add automatic marker trays back.

## Activation markers

All ordinary gameplay tokens have 32 mm bases and two native flip faces. Activation tokens have Movement on the upper face and Assault underneath; other flat tokens repeat the front symbol. The three 3D effect tokens have mirrored effect geometry on the reverse. Objectives also have mirrored reverse geometry, preserving their existing front design and decorative outer ring. Native Flip rotates the model 180 degrees about local Z. Faces and collider are centred on that pivot, with outward normals and distinct textures; no custom flip logic is bundled.

Generate artwork and source geometry, prepare the Unity input, then run BuildTokenColliders.RunActivationTokens from examples/token-collider/BuildTokenColliders.cs. The builder validates both orientations and stable table height. Keep the active-ID manifest so old cache directories cannot restore deleted tokens. Record reviewed bundle URLs in token-model-overrides.json.

## Blast Template

The custom template keeps WDS Id Token5Inch and Name Blast Template for stable references. IsTemplate=true enables native template behavior. It is a flat orange ring: 130 mm outer diameter, 126 mm inner diameter, 2 mm radial width. There is no fill or cylinder. blast-template.json pins its bundle; src/tokens/blast-template.mjs owns source and preview generation.

Build with examples/token-collider/BuildBlastTemplate.cs after scripts/prepare-token-colliders.mjs. The ring uses a native static one-bone SkinnedMeshRenderer and a full circular root MeshCollider. In the inspected native implementation, TemplateArea reads MeshFilter shapes and otherwise uses colliders; preserve and retest that contract after client changes. Local checks verify baked dimensions, a flat annulus, no fill, and centre/rim hits with square-corner misses. Native contact highlighting still needs in-game confirmation.

Do not restore a transparent filled mesh: the current loader replaces material shaders with an opaque shader. Alpha-only changes cannot make that surface invisible. Renderer.forceRenderingOff did not persist after bundle reload. The ring requires no transparency workaround or client patch.

## Shared assets and regeneration

The token artwork generator writes hash-named PNGs and token-artwork.json. The model generator writes source/preview GLBs while token-model-overrides.json preserves reviewed Unity bundles. Do not publish preview GLBs instead of tested bundles. Keep root colliders sized to the actual token and visible renderer Token tags serialized at native tag slot 20 (20020).

Use scripts/build-model-catalogue.mjs and the normal skin publisher. New native features are Test-only until production is requested. After upload, verify exact WDS IDs/names, canonical and menu defaults, model resources and thumbnail responses. Native outlines, edge dragging, flipping, contact detection and multiplayer synchronization require fresh client checks.

Retired current-game associations are removed with RemoveSkinUsage (itemInstanceId, skinId, costumeDefault). Verify readback and retain assets still referenced by another active game or the release branch. Reconcile owned skins before retrying an uncertain create request. Keep active publication checkpoints and source caches.

## Native measurement footprint

All ordinary gameplay tokens and the five objective tokens set RadiusBaseDiameterMm=32. This native field controls circular base-edge measurement and radius rings, without resizing their existing skins. The explicitly sized 130 mm Blast Template is excluded. Objectives deploy through DeploymentTerrains with IsToken=true and are no longer terrain. See mission-markers.md.

## Fire Wall template

Fire Wall is an explicitly sized template rather than a normal 32 mm reminder. Its outer oval is 40 x 100 mm, matching the reviewed Hydralisk footprint. The visible orange outline has no fill; the native TemplateArea receives an independent filled oval collider through the same skinned-renderer arrangement as Blast Template. IsTemplate=true is set and RadiusBaseDiameterMm is omitted. Source geometry is in src/tokens/fire-wall-template.mjs; fire-wall-template.json pins the Windows Unity bundle built by BuildFireWallTemplate.Run. The normal token builder skips this dedicated template. Keep its existing exact menu name and canonical sc_token_fire_wall binding.

## Wall and Flamer templates

The 40 x 100 mm oval is now displayed as Wall Template, for shared use by Firebat and other wall effects. Its canonical skin profile remains sc_token_fire_wall; the native token ID and menu skin name are Starcraft - Token - Wall Template. Native Firebat ExtraItems migrate the old Fire Wall reference without duplicating stock. The old menu alias is retired after successful Test publication.

Flamer Template is a separate open orange template, 210.4825627 mm long and 61.2930484 mm wide. These dimensions come from the current public TTS Firebat SC_FIREBAT_FLAMER v5 constants (8.28671506700212 inches long; outline width 2.41311214 inches). The outline reference is the archived GW printable template, calibrated to its 5-inch blast circle. Only dimensions are adopted from TTS: no AIM/END handles, automatic following or Lua logic. Flamer is a normal independent native IsTemplate token, with its own filled invisible contact collider and unfilled visible ring. Its generator is flamer-template.mjs and its reviewed Unity bundle is pinned in flamer-template.json. It is available from the menu; no automatic unit attachment is implied.

## Objective and Infestation highlights

Objectives and Infestation use native Unity token bundles, with Token renderer tags serialized at native slot 20 (20020), matching Stim. For objectives, only the centre layers have this tag; both decorative outline layers remain Untagged. The root collider is centred and 32 x 32 mm, independent of the unchanged 184.4 mm control ring. marker-model-overrides.json retains objective bundles, while token-model-overrides.json retains Infestation. prepare-token-colliders.mjs writes per-part highlight metadata for token and marker inputs. BuildTokenColliders.RunMarkerHighlights rebuilds only the five objectives and Infestation. Validate serialized tags and collider size after export, then check actual hover/selection in Warhall Test.

Friendly display names are separate from immutable skin/menu IDs: Activation - blue/red and Mission marker 1..5 keep their existing IDs. Map token placements and deployment token names must use the friendly Name because native CreateToken resolves by name. The catalogue's skin-name alias still uses the stable full ID.
